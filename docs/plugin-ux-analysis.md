# 插件管理模块 UX 分析报告

> 分析日期：2026-04-26
> 分析范围：插件仓库(Plugins.vue) + 插件绑定(Linker.vue) + 相关Store/API/Types

---

## 一、当前功能流程全景图

```
插件发现 ──→ 插件导入 ──→ 插件仓库管理 ──→ 插件绑定 ──→ 应用变更 ──→ 状态维护
   │            │            │              │            │           │
   ├ AssetLib   ├ 本地目录    ├ 列表/搜索     ├ 选项目      ├ 创建符号链接  ├ 存储统计
   ├ (无推荐)    ├ 本地文件    ├ 收藏/筛选     ├ 选版本      ├ 批量应用     ├ 孤立清理
   └ (无分类)    ├ Git克隆     ├ 批量选择      ├ 选单元      └ 结果展示     ├ 重复检测
                  ├ 从项目导入  ├ 插件详情                                   └ 版本删除
                  └ AssetLib   ├ 版本管理
                               └ 更新检查
```

## 二、各环节详细梳理

| 环节 | 已实现功能 | 涉及文件 |
|------|-----------|---------|
| **插件发现** | Asset Library搜索（关键词/分类/类型/Godot版本/支持级别/排序） | `src/views/Plugins.vue` |
| **插件扫描** | 从项目扫描插件（copy/move/reference三种模式） | `src/views/Plugins.vue#L457-L479` |
| **插件导入** | 本地目录、本地文件、Git克隆、Asset Library下载、从项目导入 | `src/api/index.ts#L60-L110` |
| **插件绑定** | 选项目→选插件→选版本→选单元→设置挂载路径；批量绑定 | `src/views/Linker.vue` |
| **应用变更** | 单项目应用、批量应用；展示创建/移除/错误 | `src/views/Linker.vue#L550-L580` |
| **插件卸载** | 从仓库删除、从项目解绑、批量删除/解绑 | `src/views/Plugins.vue#L432-L445` |
| **版本管理** | 多版本共存、版本选择绑定、版本删除 | `src/views/Plugins.vue#L552-L563` |
| **更新检查** | 手动检查Git插件更新、单插件更新、批量更新API | `src/api/index.ts#L184-L186` |
| **状态维护** | 存储统计、孤立文件清理、重复检测、收藏 | `src/views/Plugins.vue#L503-L523` |
| **依赖关系** | 查看插件依赖（只读展示） | `src/views/Plugins.vue#L525-L532` |

## 三、六维度问题分析

### 维度1：操作简化

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| S1 | 5个导入入口平铺 | 🔴高 | 顶部按钮区有6个按钮（检查更新+从项目导入+从目录+从文件+Asset Library+从Git），新用户认知负担大 |
| S2 | 绑定需跳转独立页面 | 🔴高 | 想给项目装插件，必须从Plugins页→Linker页→选项目→选插件→绑定→应用，5步操作 |
| S3 | 应用变更是独立步骤 | 🟡中 | 绑定后还需手动"应用变更"才能生效，对新手不直观，应提供"绑定并应用"快捷操作 |
| S4 | 无拖拽导入 | 🟡中 | 项目管理支持拖拽，但插件导入不支持拖拽目录/文件 |
| S5 | 批量绑定路径不可自定义 | 🟡中 | 批量绑定时mount_path硬编码为`addons/{unit.name}`，无法自定义 |

### 维度2：便利性最大化

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| C1 | 插件卡片无快捷绑定入口 | 🔴高 | 插件卡片上只有"收藏"和"删除"，没有"绑定到项目"按钮，必须去Linker页 |
| C2 | 无"最近使用/常用插件" | 🟡中 | 没有基于使用频率的排序或推荐，每次都要在全部插件中寻找 |
| C3 | Asset Library搜索不持久化 | 🟡中 | 每次打开Asset Library对话框，之前的搜索条件和结果都丢失 |
| C4 | 无右键菜单 | 🟡中 | 插件卡片无右键上下文菜单，缺少快捷操作通道 |
| C5 | 无键盘快捷操作 | 🟢低 | 插件管理无专用快捷键（如Ctrl+I导入、Delete删除选中） |
| C6 | 插件详情中绑定列表只读 | 🟡中 | 插件详情中展示"挂载到N个项目"，但无法直接跳转或管理这些绑定 |

### 维度3：功能实现完成度

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| F1 | 依赖不自动解析安装 | 🔴高 | `resolvePluginDependencies`只展示依赖列表，不提供"一键安装缺失依赖" |
| F2 | 更新仅支持Git源 | 🔴高 | `checkPluginUpdates`/`updateGitPlugin`只对Git源插件有效，Asset Library和本地插件无更新路径 |
| F3 | 无插件推荐/发现机制 | 🟡中 | 除了手动搜Asset Library，无"为你推荐"、"热门插件"、"同类插件" |
| F4 | 无插件启用/禁用 | 🟡中 | 不能在不解绑的情况下临时禁用某插件（Godot项目常见需求） |
| F5 | 无插件配置管理 | 🟡中 | 很多插件有.cfg配置文件，无法在Harbor中查看/编辑 |
| F6 | 无插件导出/分享 | 🟢低 | 不能将本地插件打包分享给他人 |
| F7 | 批量更新API已有但UI未用 | 🟡中 | `batchUpdatePlugins` API已存在，但更新对话框中只能逐个更新 |

### 维度4：流程完备性

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| W1 | 无引导式首次导入 | 🔴高 | 新用户进入插件页只看到空列表+6个按钮，无引导"第一步该做什么" |
| W2 | 无端到端工作流 | 🔴高 | 从发现→导入→绑定→应用是割裂的，没有串联的向导式流程 |
| W3 | 应用后无验证反馈 | 🟡中 | 应用变更后只展示created/removed列表，不验证符号链接是否真的生效 |
| W4 | 无撤销/回滚 | 🟡中 | 应用变更后无法一键回滚到之前的状态 |
| W5 | 删除插件不检查下游影响 | 🟡中 | 删除插件时不提示"该插件正被N个项目使用"，只说"不影响已挂载副本"但实际可能造成符号链接断裂 |
| W6 | 更新后无变更日志展示 | 🟡中 | `PluginUpdateInfo`有`release_notes`字段，但更新对话框中未展示 |

### 维度5：冲突容错

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| T1 | 无符号链接健康检查 | 🔴高 | 不检测已有符号链接是否断裂/失效，用户无法感知"挂载已损坏" |
| T2 | 挂载路径冲突无检测 | 🔴高 | 两个不同插件绑定到同一项目的同一`addons/xxx`路径时，无冲突预警 |
| T3 | 重复导入处理不完善 | 🟡中 | `checkPluginDuplicate` API存在但前端未在导入流程中调用 |
| T4 | 导入失败无恢复 | 🟡中 | Git克隆或Asset Library下载中断后，无断点续传/重试机制 |
| T5 | Godot版本兼容性不强制 | 🟡中 | Godot3项目绑定Godot4插件无警告提示 |
| T6 | 依赖缺失不阻断绑定 | 🟡中 | 绑定插件时不检查其依赖是否已安装，可能造成运行时错误 |

### 维度6：场景边界

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| E1 | 仓库存储路径变更后无迁移 | 🔴高 | 设置中可改`plugin_storage_path`，但已有插件的物理文件不会迁移 |
| E2 | 无离线模式 | 🟡中 | Asset Library搜索/导入必须联网，无缓存离线可用 |
| E3 | 项目删除后绑定残留 | 🟡中 | 删除项目后，该项目的绑定记录是否清理不明确 |
| E4 | 多实例运行冲突 | 🟢低 | 无文件锁机制，多个Harbor实例同时操作可能冲突 |
| E5 | 大仓库性能 | 🟢低 | 插件列表全量加载无虚拟滚动，大量插件时可能卡顿 |

## 四、优先级排序（Top 10 改进项）

| 优先级 | 编号 | 改进项 | 预期收益 |
|--------|------|--------|---------|
| P0 | C1 | 插件卡片增加"绑定到项目"快捷入口 | 减少3步操作，核心流程大幅简化 |

## 五、分步优化计划

### 第一阶段：核心流程简化（P0）

#### 步骤1：插件卡片增加"绑定到项目"快捷入口 [C1]

**目标**：在插件卡片上直接提供绑定操作，无需跳转到Linker页

**改动范围**：
- `src/views/Plugins.vue` — 插件卡片模板增加"绑定"按钮
- 新增绑定对话框组件或复用Linker中的版本选择逻辑
- 点击后弹出项目选择器（可多选），选择版本/单元，一键绑定

**验收标准**：
- [ ] 插件卡片上有"绑定到项目"按钮
- [ ] 点击后弹出项目选择对话框
- [ ] 支持选择版本和单元
- [ ] 绑定成功后显示toast提示
- [ ] 绑定后可选择"立即应用变更"

#### 步骤2：符号链接健康检查与断裂修复 [T1]

**目标**：检测并展示符号链接断裂状态，提供修复操作

**改动范围**：
- `src/types/index.ts` — Plugin/Binding类型增加健康状态字段
- `src/api/index.ts` — 新增健康检查API调用
- `src/views/Plugins.vue` — 插件详情中展示绑定健康状态
- `src/views/Linker.vue` — 已绑定插件列表展示健康状态，提供修复按钮
- 后端需新增对应的健康检查命令（不在本次前端改动范围）

**验收标准**：
- [ ] 已绑定插件列表中展示链接健康/断裂状态
- [ ] 断裂链接有明显的视觉标识（红色警告）
- [ ] 提供"修复"按钮重新创建符号链接
- [ ] 修复后状态实时更新

#### 步骤3：删除插件前提示下游影响 [W5]

**目标**：删除插件时展示该插件被哪些项目使用，让用户知情决策

**改动范围**：
- `src/views/Plugins.vue` — 修改删除确认对话框，展示绑定项目列表
- 删除前调用 `api.getPluginBindings()` 获取绑定信息
- 如果有活跃绑定，显示警告并要求二次确认

**验收标准**：
- [ ] 删除插件时展示"该插件正被N个项目使用"
- [ ] 列出使用该插件的项目名称
- [ ] 有活跃绑定时需要二次确认
- [ ] 提示"删除后以下项目的符号链接将断裂"

### 第二阶段：操作效率提升（P1）

#### 步骤4：导入入口合并为"添加插件"下拉菜单 [S1]

**目标**：将6个平铺按钮精简为1个主按钮+下拉菜单

**改动范围**：
- `src/views/Plugins.vue` — 重构顶部操作栏
- 主按钮"添加插件"点击展开下拉菜单
- 下拉菜单项：从目录导入、从文件导入、从Git导入、从项目导入、Asset Library
- "检查更新"保留为独立按钮

**验收标准**：
- [ ] 顶部操作栏从6个按钮精简为2个（添加插件+检查更新）
- [ ] 下拉菜单包含所有5种导入方式
- [ ] 每个菜单项有图标和简短说明
- [ ] 键盘可访问（Enter/Escape）

#### 步骤5：依赖自动解析安装 [F1]

**目标**：绑定插件时自动检测并安装缺失依赖

**改动范围**：
- `src/views/Plugins.vue` — 插件详情中依赖区域增加"安装缺失依赖"按钮
- `src/views/Linker.vue` — 绑定插件时自动检查依赖，弹窗提示缺失项
- 新增依赖安装确认对话框
- 调用 `api.resolvePluginDependencies()` + 批量导入/绑定API

**验收标准**：
- [ ] 插件详情中可一键安装缺失依赖
- [ ] 绑定插件时自动检测依赖
- [ ] 缺失依赖时弹窗列出并确认安装
- [ ] 依赖安装后自动绑定到同一项目

#### 步骤6：挂载路径冲突检测 [T2]

**目标**：绑定前检测目标路径是否已被占用

**改动范围**：
- `src/views/Linker.vue` — 绑定前检查目标项目的已有绑定
- 如果 `addons/{name}` 已被其他插件占用，显示冲突警告
- 提供解决方案：更换挂载路径或先解绑冲突插件

**验收标准**：
- [ ] 绑定时检测挂载路径冲突
- [ ] 冲突时显示警告，说明哪个插件已占用该路径
- [ ] 提供更换挂载路径的选项
- [ ] 提供先解绑冲突插件的快捷操作

#### 步骤7："绑定并应用"快捷操作 [S3]

**目标**：绑定后可选择立即应用变更，合并两步为一步

**改动范围**：
- `src/views/Linker.vue` — 绑定成功后toast中增加"立即应用"按钮
- `src/views/Plugins.vue` — 快捷绑定成功后同样提供"立即应用"
- 新增"绑定并应用"组合操作

**验收标准**：
- [ ] 绑定成功后toast中有"立即应用"按钮
- [ ] 点击后自动执行applyChanges
- [ ] 应用结果在toast中反馈
- [ ] 批量绑定时同样支持"绑定并应用"

## 六、实施注意事项

1. **每步完成后需运行 `npm run build` 验证构建通过**
2. **国际化**：所有新增UI文本需同步更新 `zh-CN.ts` 和 `en.ts`
3. **暗色模式**：所有新增组件需适配暗色主题
4. **后端配合**：部分功能（如健康检查、路径迁移）需要后端新增API，需协调开发
5. **渐进式发布**：建议按阶段发布，每个阶段完成后收集用户反馈再进入下一阶段
