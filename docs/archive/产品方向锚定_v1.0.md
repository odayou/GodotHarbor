# Godot Harbor 产品方向锚定文档

> 版本：v1.0 | 日期：2026-05-26
> 状态：方向锚定，指导后续所有规划与实施

---

## 一、核心定位

**Godot Harbor = Godot 开发者体验基础设施**

让 Godot 开发体验追平甚至超越 Unity Hub / Unreal 的水平。

一句话价值主张：**5 分钟从零到可运行的 Godot 项目。**

## 二、定位推演依据

### 2.1 外部环境

#### Godot 引擎增长（2026年5月最新数据）

| 指标 | 数据 | 趋势 |
|------|------|------|
| Steam 游戏发布量 | 2019年56款 → 2025年1229款 | 指数级增长 |
| Steam 累计安装 | 48.3万(2023.4) → 179.7万(2026.2) | 3年3.7倍 |
| Reddit 社区 | 4.7万(2022.1) → 30.8万(2026.2) | 6.5倍 |
| GitHub Stars | ~80K(2023) → ~150K(2026) | 翻倍 |
| Steam 独立游戏份额 | ~5%(2022) → ~20%(2026) | 4倍 |
| GMTK Game Jam 占比 | 13%(2021) → 39%(2025) | 接近追平 Unity |

关键信号：《杀戮尖塔2》Godot 开发、首日57万并发、首周300万销量——Godot 已从"业余选择"变成"商业级选择"。

#### Godot 官方生态剧变（2026年5月22日）

Godot Asset Store 正式上线，将集成到 Godot 4.7。官方路线图明确规划：

| 官方即将推出的能力 | 对 Harbor 的影响 |
|-------------------|-----------------|
| Global Addons（跨项目共享插件） | ⚠️ 与 Harbor 核心价值部分重叠 |
| Asset Updater（插件更新检测） | ⚠️ 与 Harbor 更新检测重叠 |
| Asset Store CLI（命令行管理） | ⚠️ 与 Harbor CLI 方向重叠 |
| 付费资产（即将推出） | Harbor 的"插件包"需差异化 |
| 拖拽安装（浏览器→编辑器） | 安装体验被官方补位 |
| Discovery System（发现系统） | 官方做发现，Harbor 需做管理 |

核心判断：Godot 官方正在补齐 Harbor 试图填补的空白。Global Addons 一旦落地，"插件只需导入一次，多项目复用"这个核心价值将被引擎原生覆盖。Harbor 必须在 Godot 不做的事上建立壁垒。

#### MCP 协议已成 AI 基础设施标准

| 指标 | 数据 |
|------|------|
| 月 SDK 下载量 | ~9700万 |
| 已索引 MCP Server | 1万-1.7万+ |
| 原生支持平台 | Claude、ChatGPT、Gemini、Copilot、Cursor、VS Code |
| 财富500强采用率 | 28% |
| Gartner 预测 | 2026年底75% API 网关支持 MCP |

核心判断：MCP 是 AI 时代的"USB-C"。任何开发者工具如果不暴露 MCP 接口，将在 AI Agent 生态中被边缘化。

#### 开发环境确定性趋势

行业正在从"手动配置"走向"环境即代码"：
- Dev Containers（devcontainer.json）→ 可复现的开发环境
- IaC（Terraform/Pulumi）→ 基础设施即代码，"环境幂等性"
- GitOps → Git 作为唯一真相源
- Self-healing Infrastructure → 自动检测和修复配置漂移
- Platform Engineering → 开发者自助环境配置

核心判断："环境确定性"是整个软件工程的普遍趋势。Godot 生态目前完全缺失这一层。

#### Godot 官方优先级（godotengine.org/priorities）

官方核心关注：可靠的无头命令行导出、场景多线程性能、物理引擎现代化、渲染优化、动画系统、GDScript/.NET 改进。

关键空白：官方没有任何"开发者体验基础设施"的规划——没有 Hub、没有环境管理、没有项目模板、没有构建流水线。这是 Harbor 的空间。

### 2.2 内部文档交叉验证

| 文档 | 核心主张 | 与新定位的关系 |
|------|---------|---------------|
| 产品规划v0.1 | 插件管理(Vault)+项目绑定(Linker)+引擎管理 | 三大模块是基础，需升维 |
| 商业计划书v6.0 | 作品驱动型可持续项目 | 战略不变，但产品野心需升级 |
| 核心功能审视 | 核心价值是"管理插件生命周期" | 正确但不够，需扩展到"管理开发生命周期" |
| 评估报告 | 四大问题已解决，GUI-first 是差异化 | GUI-first 是基础，需叠加更多差异化 |
| 迭代计划v0.2 | "打开就能用，用了就管用" | 理念正确，需扩展到全生命周期 |
| 商业模式软件定位思考 | "环境确定性"是核心方向 | 是子集，需升维为"开发者体验基础设施" |

### 2.3 关键矛盾与决策

**矛盾1：官方补位 vs 差异化**

| 官方会做的 | Harbor 不做 | Harbor 做 |
|-----------|------------|----------|
| 插件安装（Asset Store） | ❌ 重新实现安装 | ✅ 管理已安装插件的生命周期 |
| 多项目共享（Global Addons） | ❌ 做另一个共享机制 | ✅ 版本锁定+环境声明+漂移检测 |
| 插件更新（Asset Updater） | ❌ 做另一个更新器 | ✅ 跨项目版本一致性管理 |
| 命令行工具（Asset Store CLI） | ❌ 做另一个 CLI | ✅ 环境还原 CLI（harbor restore） |

**矛盾2："环境确定性"不够显著**

"环境确定性"是防守型价值（防止坏事发生），不够让人主动来找。需要叠加进攻型价值（让好事更快发生）。

**矛盾3：特性矩阵太薄**

仅"环境确定性"4个特性（声明+检测+同步+MCP），每个都是一层逻辑，竞品一周能复刻。需要更厚的特性矩阵和网状耦合。

**决策：升维到"开发者体验基础设施"**

## 四、四大特性域详细设计

### 4.1 项目启动（Template Hub）

#### 核心价值

**5分钟从零到可运行的 Godot 项目。**

不是"空项目模板"，是"带最佳实践的全栈模板"。

#### 模板定义

一个模板 = 引擎版本 + 插件列表 + 项目配置 + 导出预设 + README + .harbor.yml

```yaml
# template.yml — 模板定义文件
name: "2D Platformer Starter"
description: "完整的2D平台游戏起步包"
godot_version: "4.4.1"
author: "community"
tags: ["2d", "platformer", "starter"]

plugins:
  - name: phantom-camera
    version: "1.2.0"
    source: asset-store
  - name: dialogic
    version: "2.0.0-beta8"
    source: git
    ref: "v2.0.0-beta8"

project_config:
  input_mappings: "preset/platformer_inputs"
  render_mode: "canvas_item"
  window_size: [1280, 720]

export_presets:
  - platform: "windows"
    name: "Windows Desktop"
  - platform: "web"
    name: "HTML5"

post_setup:
  - action: "open_readme"
    message: "查看快速开始指南"
```

#### 模板分类

| 类别 | 示例模板 |
|------|---------|
| 游戏类型 | 2D平台、2D RPG、2D肉鸽、3D FPS、3D第三人称、视觉小说、卡牌游戏 |
| 技术栈 | 多人游戏（Nakama）、手机游戏（广告+内购）、Steam集成、Mod支持 |
| 学习用 | GDScript入门、C#入门、GDExtension(C++)入门、Shader入门 |
| 空白 | 最小项目（仅引擎+推荐插件）、空白4.x、空白3.x |

#### 模板市场

- 社区可提交模板（GitHub PR 或模板提交表单）
- 模板评分+评论（复用 Asset Store 的评价体系思路）
- 模板标签+搜索
- 官方精选模板（Harbor 内置 5-10 个高质量模板）
- 模板使用统计

#### 与 Global Addons 的差异

| 维度 | Global Addons | Harbor 模板 |
|------|-------------|------------|
| 解决的问题 | "插件装一次到处用" | "项目从零到可运行" |
| 包含内容 | 仅插件 | 引擎+插件+配置+导出预设+README |
| 版本管理 | 无（装最新） | 精确锁定 |
| 环境一致性 | 无 | .harbor.yml 声明+漂移检测 |
| 网络效应 | 无 | 模板市场+社区贡献 |

#### 技术实现要点

- 模板存储：`~/.godot-harbor/templates/{template_id}/`
- 模板实例化：创建项目目录 → 复制项目骨架 → 安装引擎 → 安装插件 → 应用配置 → 生成 .harbor.yml
- 模板更新：模板有新版本时，已基于旧模板创建的项目可选择升级
- 模板导入：从 Git URL 导入模板定义

### 4.2 日常开发（Environment Management）

#### 核心价值

**让 Godot 项目的开发环境像代码一样可版本化、可复现、可同步。**

#### 4.2.1 环境声明（.harbor.yml）

```yaml
# .harbor.yml — 项目环境声明（提交到 Git）
version: 1

godot:
  version: "4.4.1"
  mono: false

plugins:
  - name: phantom-camera
    version: "1.2.0"
    source: asset-store
    mount: copy
  - name: dialogic
    version: "2.0.0-beta8"
    source: git
    url: "https://github.com/dialogic-godot/dialogic.git"
    ref: "v2.0.0-beta8"
    mount: copy

settings:
  mount_strategy: copy
  auto_sync: true
```

#### 4.2.2 环境漂移检测

启动时自动对比 .harbor.yml 声明 vs 实际状态：

```
✅ Godot 4.4.1 — 已安装
⚠️ phantom-camera v1.2.0 — 当前 v1.1.0（版本漂移）
❌ dialogic v2.0.0-beta8 — 未安装
✅ mount_strategy: copy — 一致
```

漂移检测触发时机：
- 应用启动时（自动）
- 切换 Git 分支后（.harbor.yml 变化时）
- 手动触发

#### 4.2.3 一键同步

检测到漂移后，一键修复所有不一致：
- 自动下载/切换引擎版本
- 自动安装/升级/降级插件
- 自动应用绑定
- 生成同步报告

#### 4.2.4 插件推荐

基于项目类型和已有插件，推荐可能需要的插件：
- 新建2D项目 → 推荐 Phantom Camera、Dialogic、Aseprite Importer
- 使用 C# → 推荐 C# 相关工具插件
- 基于模板创建 → 推荐模板生态插件

推荐来源：
- 模板中的插件组合
- 社区使用统计（"使用此插件的项目还使用了..."）
- 编辑精选

#### 4.2.5 与 Global Addons 的差异

| 维度 | Global Addons | Harbor 环境管理 |
|------|-------------|----------------|
| 版本锁定 | 无（全局一个版本） | ✅ 项目级精确锁定 |
| 团队同步 | 无 | ✅ .harbor.yml + Git |
| 漂移检测 | 无 | ✅ 启动时自动检测 |
| 离线/内网 | 需网络 | ✅ 本地仓库 |
| 多版本并存 | 不支持 | ✅ 同一插件多版本共存 |
| 跨引擎版本兼容 | 无 | ✅ Godot 3/4 兼容性检测 |

### 4.3 构建发布（Build Pipeline）

#### 核心价值

**让 Godot 项目的构建发布从"手动折腾"变成"一键完成"。**

#### 4.3.1 导出模板管理

Godot 导出是公认的痛点：下载导出模板、配置签名、处理平台差异。

Harbor 解决：
- 导出模板自动管理（检测版本、自动下载、版本匹配）
- 导出模板缓存（多版本并存、增量下载）
- 导出模板健康检查（完整性校验）

#### 4.3.2 导出预设模板化

一键配置常见平台的导出预设：

| 平台 | 预设内容 |
|------|---------|
| Windows | 图标、签名、架构选择 |
| macOS | Bundle ID、签名、公证、架构 |
| Linux | AppImage/Flatpak 配置 |
| Android | keystore 签名、min SDK、权限、ABI |
| iOS | 证书、Profile、Bundle ID |
| Web | HTML 模板、压缩、CORS |
| Steam | Steam SDK 集成、depot 配置 |

预设可保存、导出、共享（JSON 格式，提交到 Git）。

#### 4.3.3 多平台批量构建

- 选择项目 → 选择目标平台 → 一键构建所有平台
- 构建队列管理（并行/串行）
- 构建进度实时展示
- 构建产物管理（版本号、日期、平台标签）

#### 4.3.4 CI/CD 配置生成

- 一键生成 GitHub Actions workflow（Godot 导出 + 多平台构建）
- 一键生成 GitLab CI 配置
- 支持 headless 导出模式
- 构建缓存策略（避免每次全量构建）

#### 4.3.5 构建缓存

- 增量构建（仅重新导出变化的资源）
- 构建产物版本管理
- 构建历史记录

#### 4.3.6 与 Godot 官方优先级的关系

Godot 官方优先级明确写了"Reliable headless command line export"——这说明官方也在改善导出，但官方只改善引擎侧的导出能力，不提供：
- 导出预设管理
- 多平台批量构建
- CI/CD 配置生成
- 签名/证书管理

这些是 Harbor 的空间。

### 4.4 AI 协作（MCP Server）

#### 核心价值

**让 AI Agent 能理解并操作 Godot 项目的完整开发环境。**

#### 4.4.1 MCP Server 能力定义

**Tools（AI 可调用）：**

| Tool | 功能 | 优先级 |
|------|------|--------|
| `sync_environment` | 一键同步项目环境 | P0 |
| `check_drift` | 检测环境漂移 | P0 |
| `install_plugin` | 安装指定版本插件 | P0 |
| `switch_engine` | 切换引擎版本 | P1 |
| `create_from_template` | 从模板创建项目 | P1 |
| `build_project` | 构建项目 | P2 |
| `check_updates` | 检查插件/引擎更新 | P1 |

**Resources（AI 可读取）：**

| Resource | 内容 | 优先级 |
|----------|------|--------|
| `harbor://project/{id}/environment` | 项目当前环境状态 | P0 |
| `harbor://project/{id}/expected` | 项目期望环境（.harbor.yml） | P0 |
| `harbor://project/{id}/drift` | 环境漂移报告 | P0 |
| `harbor://plugins/available` | 可用插件列表 | P1 |
| `harbor://engines/installed` | 已安装引擎列表 | P1 |
| `harbor://templates` | 可用模板列表 | P1 |
| `harbor://project/{id}/structure` | 项目结构概览 | P2 |

**Prompts（AI 可使用）：**

| Prompt | 功能 | 优先级 |
|--------|------|--------|
| `diagnose_environment` | 诊断环境问题 | P1 |
| `suggest_plugins` | 基于项目类型推荐插件 | P1 |
| `setup_ci_cd` | 生成 CI/CD 配置 | P2 |

#### 4.4.2 使用场景

场景1：开发者在 Cursor 中说"帮我配置这个 Godot 项目的开发环境"
→ AI Agent 调用 `harbor://project/{id}/expected` 读取 .harbor.yml
→ 调用 `check_drift` 检测漂移
→ 调用 `sync_environment` 一键同步

场景2：开发者在 Claude 中说"帮我给这个2D平台游戏添加对话系统"
→ AI Agent 调用 `harbor://project/{id}/environment` 了解当前环境
→ 调用 `suggest_plugins` 获取推荐
→ 调用 `install_plugin` 安装 Dialogic
→ 调用 `sync_environment` 应用变更

场景3：开发者在 VS Code Copilot 中说"帮我构建 Android 版本"
→ AI Agent 调用 `harbor://project/{id}/environment` 检查引擎版本
→ 调用 `build_project` 触发构建
→ 返回构建结果

#### 4.4.3 技术实现

- MCP Server 作为独立进程运行（stdio 传输）
- 使用官方 MCP SDK（TypeScript 或 Rust）
- 与 Harbor 后端共享数据目录（~/.godot-harbor/）
- 权限控制：只读操作无需确认，写操作需用户确认

## 五、差异化壁垒

### 5.1 壁垒矩阵

| 壁垒 | 说明 | 复刻难度 |
|------|------|---------|
| 环境漂移检测 | Global Addons 不做，Asset Store 不做 | 中（逻辑不复杂，但需要持续维护检测规则） |
| MCP Server | AI Agent 可直接操作 Godot 项目环境，竞品为零 | 高（需要完整的数据层+API层） |
| 多版本管理 | 同一插件多版本并存+项目级绑定 | 中（Global Addons 只装最新） |
| 模板市场 | 网络效应：模板越多→用户越多→模板越多 | 高（需要社区冷启动） |
| 构建流水线 | 导出预设+CI/CD生成+批量构建 | 高（需要深入理解各平台导出细节） |
| 跨平台 GUI | gd-plug/GodotEnv 是 CLI，Harbor 是唯一 GUI 方案 | 中（GUI 开发成本高） |

### 5.2 与竞品的定位对比

| 竞品 | 定位 | 与 Harbor 关系 |
|------|------|-------------|
| Godot Asset Store | 官方资产发现+安装 | 互补（Store 做发现，Harbor 做管理） |
| Global Addons | 官方多项目共享 | 部分重叠（Harbor 在版本管理+环境确定性+模板上差异化） |
| gd-plug | CLI 插件管理 | 不同范式（CLI vs GUI），Harbor 覆盖更广 |
| GodotEnv | CLI 引擎+插件管理 | 同上 |
| Global Asset Manager | 编辑器内资产浏览+复制 | 不同层级（资产浏览 vs 环境管理） |
| Unity Hub | 引擎+项目管理 | 参考对标，Harbor 目标是成为"Godot 的 Unity Hub" |

Harbor 的独特位置：**唯一提供"开发者体验基础设施"能力的 Godot 工具。没有竞品。**

## 六、商业策略

### 6.1 战略不变：作品驱动型可持续项目

商业计划书v6.0的核心战略仍然正确：
- 不靠 Harbor 本身赚钱，靠 Harbor 带来的影响力赚钱
- GitHub Sponsors / 爱发电覆盖开发成本
- 保留商业化预留接口

### 6.2 商业化触发条件调整

| 触发条件 | 原阈值 | 调整后阈值 | 理由 |
|----------|--------|-----------|------|
| GitHub Stars | 5,000+ | 3,000+ | 产品覆盖面更广，用户增长更快 |
| 月活用户 | 10,000+ | 5,000+ | 同上 |
| Godot 市场份额 | 15%+ | 15%+ | 不变 |
| 社区主动需求 Cloud | 50+ 条 | 30+ 条 | 模板市场+构建流水线会带来更多付费需求 |

### 6.3 商业化路线图调整

原优先级：插件包/模板包 > Cloud > Team > 市场 > 企业

调整后优先级：**环境包 > 模板市场 > Cloud > Team > 市场 > 企业**

"环境包"定义：打包完整环境配置（引擎+插件+导出预设+CI/CD配置）的一键还原方案。
- 区别于"插件包"（只卖插件），"环境包"卖的是"完整解决方案"
- 示例："商业级2D RPG 环境包" = Godot 4.4.1 + 10个精选插件 + 导出预设 + GitHub Actions workflow + 部署脚本

## 十、总结

Godot Harbor 的核心方向从"插件管理工具"升级为"Godot 开发者体验基础设施"。

核心价值提供：**让 Godot 项目的开发环境像代码一样可版本化、可复现、可同步，让开发者5分钟从零到可运行的项目。**

四大特性域：
1. **项目启动**（Template Hub）— 5分钟开干
2. **日常开发**（Environment Management）— 环境确定性
3. **构建发布**（Build Pipeline）— 一键导出
4. **AI 协作**（MCP Server）— AI 可理解的环境上下文

差异化壁垒：环境漂移检测（官方不做）、MCP Server（竞品为零）、模板市场（网络效应）、构建流水线（高复刻成本）。

商业策略不变：作品驱动型可持续项目，保留商业化预留接口。
