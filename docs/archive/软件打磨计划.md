## 二、🔴 阻断性问题

### B1. MCP Server：用户完全不知道怎么用

**现状**：
- MCP Tab 在 Build 页面中，入口不显眼
- 启动 MCP Server 后，只显示"运行中/已停止"状态
- Resources/Tools/Prompts 只显示数量（7/7/3），不显示具体内容
- 配置 JSON 中的 `command` 是 `harbor-mcp-server`，但用户不知道这个可执行文件在哪
- 没有说明如何验证 MCP 是否工作
- 没有说明除了 Claude Desktop 和 Cursor 之外还能怎么用
- `harbor-mcp-server` 可执行文件可能不在 PATH 中，用户需要手动指定完整路径

**影响**：MCP 是核心卖点，但用户完全无法上手

**修复方案**：
1. MCP Tab 中展示 Resources/Tools/Prompts 的具体列表（名称+描述）
2. 配置 JSON 中自动填入 `harbor-mcp-server` 的完整路径（`getMcpServerPath()` 已有）
3. 添加"测试连接"按钮——启动后自动验证 MCP 协议握手
4. 添加使用指南：步骤说明 + 常见问题
5. 更新数量显示（现在是 9/10/3，硬编码的 7/7/3 已过时）

### B2. CI/CD：生成的配置未使用 .harbor.yml 中的 CI 声明

**现状**：
- .harbor.yml 支持 `ci` 字段（provider + platforms）
- 但 CI Tab 的 UI 完全不读取这个字段
- 用户需要手动选择 provider/platforms/godot_version
- 即使项目已有 .harbor.yml 声明了 CI 配置，UI 也不会预填

**影响**：.harbor.yml 的 CI 声明形同虚设

**修复方案**：
1. CI Tab 选择项目后，自动从 .harbor.yml 读取 ci 配置预填
2. 如果 .harbor.yml 没有 ci 配置，从 godot 字段推断版本号
3. 生成 CI 配置后，自动保存到 .harbor.yml 的 ci 字段

### B3. MCP Server：`start_mcp_server` 在应用内启动，但 MCP 协议是 stdio

**现状**：
- `start_mcp_server` 在 Tauri 应用内启动一个线程运行 MCP server
- MCP 协议通过 stdio 通信
- 但在应用内启动的 MCP server 的 stdin/stdout 被应用自身占用
- 外部客户端（Claude Desktop/Cursor）无法连接到这个实例
- 正确的使用方式应该是独立运行 `harbor-mcp-server` 可执行文件

**影响**：UI 上的"启动/停止"按钮实际上对外部客户端没有意义

**修复方案**：
1. 将"启动/停止"改为"检测运行状态"+ 引导用户独立启动
2. 或者提供"复制启动命令"功能（`harbor-mcp-server` 的完整路径）
3. 保留启动/停止功能用于内部测试，但明确标注"仅供测试"

## 三、🟡 显著问题

### S1. MCP Resources/Tools/Prompts 数量硬编码

**现状**：Build.vue 中 `Resources (7)` `Tools (7)` `Prompts (3)` 是硬编码的

**修复**：从后端动态获取数量，或至少更新为正确数字（9/10/3）

### S2. CI Tab 的 Godot 版本需要手动输入

**现状**：用户需要手动输入 Godot 版本号（如 4.4.1），容易输错

**修复**：选择项目后自动从项目信息或已安装引擎列表中预填

### S3. 构建 Tab 没有导出模板安装状态提示

**现状**：用户点击"开始构建"时，如果导出模板未安装，构建会失败但错误信息不够明确

**修复**：构建前检查导出模板是否已安装，未安装则提示并引导安装

### S4. MCP 配置 JSON 缺少 VS Code / Trae 等客户端

**现状**：只提供 Claude Desktop 和 Cursor 两种客户端配置

**修复**：添加 VS Code (Copilot)、Trae、Windsurf 等客户端配置说明

### S5. 构建历史没有持续时间计算

**现状**：`BuildRecord` 中 `duration_secs` 始终为 0（代码中 `let duration = 0u64;`）

**修复**：用 `completed_at - started_at` 计算实际持续时间

### S6. MCP Server 运行状态轮询效率低

**现状**：每 5 秒轮询一次 MCP 运行状态，即使页面不可见也在轮询

**修复**：使用 Tauri 事件推送替代轮询，或页面不可见时暂停轮询

### S7. 导出模板下载没有镜像源支持

**现状**：Godot 官方下载源在国内很慢，没有镜像选项

**修复**：在设置中添加导出模板下载镜像源配置

### S8. CI 生成的 YAML 没有使用 Harbor MCP

**现状**：生成的 GitHub Actions / GitLab CI 配置是纯 Godot 构建，没有集成 Harbor 环境同步

**修复**：在 CI 配置中添加 Harbor 环境同步步骤（读取 .harbor.yml → 安装插件 → 构建）

## 四、🟢 小问题

### M1. Build 页面 Tab 过多（5个）

**现状**：模板/预设/构建/CI/MCP 五个 Tab 挤在一个页面

**建议**：长期考虑拆分，短期可接受

### M2. 构建记录的 `openInFileManager` 可能路径不存在

**现状**：构建输出目录可能已被删除

**修复**：打开前检查路径是否存在

### M3. MCP Server 停止按钮文案有 fallback

**现状**：`t('mcp.stopServer') || '停止服务'` 说明 i18n key 可能缺失

**修复**：确认 i18n key 存在

### M4. CI Tab 没有保存上次选择

**现状**：切换 Tab 后选择的项目/provider 丢失

**修复**：使用 localStorage 或 Pinia 持久化

### M5. 导出预设的"应用"操作没有确认提示

**现状**：点击"应用预设"直接覆盖 export_presets.cfg

**修复**：添加确认对话框
