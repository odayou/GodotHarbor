# Godot Harbor 后续迭代规划 v0.2

基于产品规划 v0.1 和当前实现状态，围绕**易用性**、**痛点解决**和**功能完备性**三个维度，规划后续迭代方向。

---

## 一、核心设计理念

> **"打开就能用，用了就管用"**

Godot 编辑器本身的体验值得借鉴——不管安装什么版本，打开就能看到所有项目。Godot Harbor 应该达到同样的零门槛体验：**启动即发现，发现即管理**。

---

## 二、迭代方向总览

| 方向 | 核心目标 | 优先级 |
|------|----------|--------|
| A. 零门槛启动体验 | 打开即用，无需配置 | P0 |
| B. 项目信息实时性 | 信息不滞后，改名/迁移自动感知 | P0 |
| C. 交互细节打磨 | 弹窗/快捷键/空状态/一致性 | P1 |
| D. 功能完备性 | 补齐产品规划中的缺失能力 | P1 |
| E. 性能与架构 | 首屏优化、状态管理、响应速度 | P2 |

## A. 零门槛启动体验（P0）

### A1. 启动时自动扫描项目

**痛点**：当前必须手动点击"扫描项目"才能发现项目，新用户首次打开看到空列表，不知道该做什么。

**目标**：像 Godot 编辑器一样，打开应用就自动展示所有本地 Godot 项目。

**实现方案**：
1. 应用启动时，自动读取已配置的扫描目录，后台静默扫描
2. 首次使用无扫描目录时，自动扫描常见位置：
   - Windows: `D:\`, `C:\Users\<user>\Documents\`, 桌面
   - macOS: `~/Documents/`, `~/Developer/`, `~/Projects/`
   - Linux: `~/Documents/`, `~/projects/`, `~/src/`
3. 扫描结果与已有项目合并（增量更新，不覆盖用户手动修改的信息）
4. 扫描过程不阻塞 UI，后台执行完成后通知前端刷新

**关键代码变更**：
- `lib.rs` setup 钩子中触发自动扫描
- 新增 `auto_scan_on_startup` 设置项（默认开启）
- 前端监听 `scan-complete` 事件自动刷新列表

### A2. 侧边栏添加首页入口

**痛点**：用户离开首页后无法通过 UI 返回首页，只能手动修改 URL。

**实现方案**：
- Sidebar.vue 的 menuItems 顶部添加 Home 入口
- 使用独立的首页图标（仪表盘/概览图标）
- 首页路由高亮使用 `route.path === '/'` 匹配

### A3. 首屏加载优化（消除白屏闪烁）

**痛点**：Tauri 窗口先显示空白页面，Vue 挂载完成后才显示内容，用户看到明显白屏。

**实现方案**：
1. `tauri.conf.json` 设置窗口 `"visible": false`
2. `App.vue` 的 `onMounted` 中调用 `getCurrentWindow().show()`
3. `index.html` 中添加内联 CSS loading 动画作为占位
4. 首页统计数据使用后端聚合接口（一次请求获取所有统计），替代当前 N+1 请求

### A4. 引擎自动发现

**痛点**：用户必须手动注册引擎路径，不知道引擎装在哪里。

**实现方案**：
1. 应用启动时自动扫描常见 Godot 引擎安装位置：
   - Windows: `C:\Program Files\Godot\`, `C:\Program Files (x86)\Godot\`, Scoop/GodotMgr 路径
   - macOS: `/Applications/Godot.app/`, Homebrew 路径
   - Linux: `/usr/bin/godot`, `/usr/local/bin/godot`, `~/.local/bin/godot`
2. 扫描 PATH 环境变量中的 `godot` 可执行文件
3. 发现的引擎自动注册，用户可在设置中关闭自动发现

## B. 项目信息实时性（P0）

### B1. 项目路径有效性实时校验

**痛点**：项目目录被删除、移动或重命名后，应用内信息持续滞后，状态标签仍显示"就绪"。

**实现方案**：
1. `get_projects` 命令增加实时校验：检查路径是否存在、project.godot 是否可解析
2. 路径失效的项目标记为 `MissingSource` 状态
3. 前端项目卡片对 `MissingSource` 状态显示特殊样式（灰色/虚线边框）+ "重新定位"按钮
4. "重新定位"功能：用户选择新路径，系统验证 project.godot 后更新项目信息

### B2. 项目改名/迁移智能检测

**痛点**：用户在文件系统中重命名项目目录后，旧记录指向不存在的路径，新路径被视为全新项目，分组/引擎绑定等关联信息丢失。

**实现方案**：
1. 扫描时检测"旧路径失效 + 出现同名新项目"的情况
2. 弹出提示："检测到项目 'XXX' 可能已移动到新路径，是否更新？"
3. 用户确认后，将旧 project_id 的所有关联信息（绑定、分组、引擎绑定）迁移到新路径
4. 保留 project_id 不变，仅更新 path 字段

**关键算法**：
```
扫描发现新项目 → 检查是否有同名旧项目且路径失效 → 提示用户 → 迁移关联数据
```

### B3. 项目信息增量同步

**痛点**：扫描时只更新 name 和 godot_version，不更新 icon_path 和 status。

**实现方案**：
1. 扫描匹配到已有项目时，同步更新所有字段：name、godot_version、icon_path、status
2. 保留用户手动修改的字段（如 group、自定义名称）
3. 新增 `last_synced_at` 时间戳，标记最后一次自动同步时间

### B4. 文件系统变更监听

**痛点**：应用运行期间，用户在文件系统中的操作（改名、移动、删除）无法实时反映。

**实现方案**：
1. 使用 `notify` crate 监听已注册扫描目录的文件系统变更
2. 检测到 project.godot 文件变化时，触发增量扫描
3. 通过 Tauri 事件通知前端刷新
4. 可配置的防抖间隔（默认 5 秒），避免频繁刷新

## C. 交互细节打磨（P1）

### C1. 弹窗 Escape 键关闭 + 遮罩层点击关闭

**痛点**：所有弹窗只能通过按钮关闭，无法按 Escape 或点击遮罩层关闭，不符合桌面应用习惯。

**实现方案**：
1. 创建通用 `useDialog` composable，统一管理弹窗状态
2. 弹窗打开时注册 Escape 键监听，关闭时注销
3. 遮罩层添加 `@click="close"` 事件
4. 所有弹窗统一迁移到 `useDialog`

### C2. 统一删除确认对话框

**痛点**：Projects 使用自定义对话框，Plugins 和 Engines 使用 `window.confirm()`，风格不统一。

**实现方案**：
1. 创建通用 `ConfirmDialog` 组件
2. 支持：标题、描述、确认按钮文字/颜色、取消按钮
3. 所有删除操作统一使用 `ConfirmDialog`
4. 替换所有 `window.confirm()` 调用

### C3. 全局快捷键扩展

**痛点**：仅有 Ctrl+T/Ctrl+D 两个主题切换快捷键，功能重复，缺少导航和操作快捷键。

**实现方案**：

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+1` | 跳转首页 |
| `Ctrl+2` | 跳转项目 |
| `Ctrl+3` | 跳转插件 |
| `Ctrl+4` | 跳转绑定 |
| `Ctrl+5` | 跳转引擎 |
| `Ctrl+,` | 打开设置 |
| `Ctrl+K` | 全局搜索（命令面板） |
| `Ctrl+R` | 刷新当前页面数据 |
| `Escape` | 关闭当前弹窗 |
| `Ctrl+N` | 新建/添加（上下文相关） |

### C4. 空状态添加操作引导按钮

**痛点**：空状态只有文字说明，没有直接的操作按钮，用户需要自己找到对应功能入口。

**实现方案**：
- 项目空状态 → 添加"扫描项目"和"添加项目"按钮
- 插件空状态 → 添加"从目录导入"和"从 Git 导入"按钮
- 引擎空状态 → 添加"注册引擎"按钮
- 绑定空状态 → 添加"前往项目"按钮

### C5. OnboardingGuide 持久化跳过状态

**痛点**：用户跳过引导后，下次打开应用如果仍无项目/插件，引导会再次出现。

**实现方案**：
1. 跳过/完成后在 settings.json 中写入 `"onboarding_completed": true`
2. 检查时先读取此标志，已完成则不再显示
3. 设置页提供"重新显示引导"选项

### C6. 侧边栏折叠功能

**痛点**：侧边栏固定 256px，小窗口下挤压主内容区域。

**实现方案**：
1. 添加折叠/展开按钮（侧边栏底部或顶部）
2. 折叠后仅显示图标（64px），展开显示图标+文字（256px）
3. 折叠状态持久化到 settings.json
4. 快捷键 `Ctrl+B` 切换侧边栏

## D. 功能完备性（P1）

### D1. 全局搜索/命令面板

**痛点**：项目多、插件多时，需要在不同页面之间跳转查找，效率低。

**实现方案**：
1. `Ctrl+K` 打开全局搜索面板（类似 VS Code 命令面板）
2. 可搜索：项目名称、插件名称、引擎、设置项、操作命令
3. 搜索结果分类展示，点击直接跳转或执行
4. 支持模糊匹配和拼音搜索

### D2. 项目自定义名称

**痛点**：项目名称只能从 project.godotot 读取，用户无法在 Harbor 中给项目起别名（如"主项目"、"测试项目"）。

**实现方案**：
1. Project 模型新增 `display_name` 字段（可选）
2. 项目卡片优先显示 display_name，无则显示 name
3. 项目详情弹窗中添加"自定义名称"输入框
4. 扫描同步时不覆盖 display_name

### D3. 插件使用统计

**痛点**：用户不知道哪些插件最常用、哪些从未被使用。

**实现方案**：
1. 首页展示"最常用插件"排行
2. 插件卡片显示"被 N 个项目使用"
3. 插件列表支持按使用数量排序
4. 未被任何项目使用的插件标记"闲置"标签

### D4. 批量操作

**痛点**：需要逐个操作项目/插件，无法批量绑定、批量删除。

**实现方案**：
1. 项目列表支持多选（Ctrl+点击 / Shift+点击）
2. 批量绑定：选择多个项目 → 选择插件 → 一键绑定
3. 批量删除：选择多个项目/插件 → 确认后批量删除
4. 批量应用变更：选择多个项目 → 一键应用所有待变更

### D5. 项目最近打开时间

**痛点**：项目列表无法按最近使用排序，找不到最近在开发的项目。

**实现方案**：
1. Project 模型新增 `last_opened_at` 字段
2. 通过引擎启动项目时更新此字段
3. 项目列表默认按 `last_opened_at` 降序排列
4. 首页展示"最近打开的项目"

### D6. 插件更新一键应用

**痛点**：检测到插件有新版本后，需要手动重新导入、重新绑定、重新应用变更，步骤繁琐。

**实现方案**：
1. 插件详情中显示"更新可用"标识
2. 一键更新：拉取新版本 → 自动创建新版本 → 已绑定的项目自动升级绑定 → 提示用户应用变更
3. Git 插件：使用 git_store_dir 中的 .git 执行 `git pull`
4. Asset Library 插件：重新下载最新版本

### D7. 项目模板/预设

**痛点**：新建项目时需要重复绑定相同的插件组合。

**实现方案**：
1. 允许将一个项目的插件绑定关系保存为"模板"
2. 新项目可基于模板一键绑定所有插件
3. 模板可导出/导入（JSON 格式），方便团队共享
4. 与现有"团队配置"功能整合

## E. 性能与架构（P2）

### E1. Pinia Store 集成

**痛点**：4 个 Pinia store 已定义但未被使用，状态分散在各组件内部，相同数据被重复请求。

**实现方案**：
1. 所有页面通过 Store 获取和修改数据，不再直接调用 api
2. Store 作为单一数据源，组件从 Store 读取
3. 数据变更通过 Store action 统一处理，自动通知所有订阅组件
4. 添加缓存策略：Store 数据 30 秒内不重复请求

### E2. 首页统计后端聚合接口

**痛点**：首页统计需要 N+1 次请求（1 次获取项目列表 + N 次获取每个项目的绑定数）。

**实现方案**：
1. 新增 `get_dashboard_stats` 命令，一次返回所有统计
2. 返回：项目数、插件数、绑定数、最近打开项目、常用插件、待更新插件数
3. 首页只需一次请求即可渲染

### E3. 骨架屏替代 Spinner

**痛点**：加载时使用旋转 spinner，页面布局跳变明显。

**实现方案**：
1. 创建通用 Skeleton 组件（卡片骨架、列表骨架、表格骨架）
2. 各页面用 Skeleton 替代 spinner
3. Skeleton 尺寸与实际内容一致，避免布局跳变

### E4. 路由守卫与页面标题

**痛点**：切换页面时窗口标题不变，无滚动位置恢复。

**实现方案**：
1. `router.beforeEach` 中更新窗口标题为 "Godot Harbor - {页面名}"
2. 配置 `scrollBehavior` 恢复滚动位置
3. 路由 meta 中配置页面标题和所需数据预加载

## 四、关键体验指标

| 指标 | 当前 | 目标 |
|------|------|------|
| 首次打开到看到项目列表 | 需手动扫描 3~5 步 | 自动展示，0 步 |
| 首屏白屏时间 | ~1s 空白 | <200ms（splash + 延迟显示） |
| 项目改名后信息更新 | 永不更新（需手动重新扫描） | 自动检测并提示 |
| 项目路径失效发现 | 永不发现 | 实时标记 MissingSource |
| 弹窗关闭方式 | 仅按钮 | 按钮 + Escape + 遮罩层 |
| 删除确认一致性 | 混合（自定义 + window.confirm） | 统一自定义对话框 |
| 全局快捷键 | 2 个（重复功能） | 10+ 个（导航/操作/搜索） |
| 首页统计请求次数 | N+1 | 1 |
| 引擎注册 | 手动指定路径 | 自动发现 + 手动补充 |
