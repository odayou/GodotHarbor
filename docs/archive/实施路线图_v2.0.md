> 基于《产品方向锚定_v1.0》制定

## 总览

```
Phase 0: 基础设施准备（Asset Store 适配 + 数据模型扩展）
    ↓

    ↓
```

## Phase 0：基础设施准备

> 目标：适配新 Asset Store API，扩展数据模型，为后续 Phase 打基础

### 0.1 Asset Store 新 API 适配

**背景**：Godot Asset Store 于 2026-05-22 上线，将集成到 Godot 4.7。旧 Asset Library 即将废弃。

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 研究 Asset Store API | 分析新 API 端点、认证方式、数据结构 | P1 |
| 实现新 API 客户端 | 替换旧 Asset Library API 调用 | P1 |
| 适配搜索+下载流程 | 搜索、详情、下载、版本选择 | P1 |
| 旧 API 兼容层 | 保留旧 API 支持（4.7 之前的用户） | P2 |
| 用户认证集成 | Asset Store 使用 Godot 共享账号系统 | P2 |

### 0.2 数据模型扩展

| 任务 | 说明 | 优先级 |
|------|------|--------|
| Template 数据模型 | Template + TemplatePlugin + TemplateConfig | P0 |
| .harbor.yml 扩展 | 增加 godot 版本、导出预设、CI/CD 配置字段 | P0 |
| ExportPreset 数据模型 | 导出预设定义 | P1 |
| BuildRecord 数据模型 | 构建记录 | P2 |
| DriftReport 数据模型 | 环境漂移报告 | P0 |

### 0.3 .harbor.yml v2 规范

```yaml
# .harbor.yml v2
version: 2

godot:
  version: "4.4.1"
  mono: false

plugins:
  - name: phantom-camera
    version: "1.2.0"
    source: asset-store
    mount: copy
  - name: dialogic
    version: "2.0.0-beta8"
    source: git
    url: "https://github.com/dialogic-godot/dialogic.git"
    ref: "v2.0.0-beta8"
    mount: copy

export_presets:
  - platform: "windows"
    name: "Windows Desktop"
    config: {} # 平台特定配置
  - platform: "web"
    name: "HTML5"
    config: {}

ci:
  provider: "github-actions"
  platforms: ["windows", "web", "linux"]

settings:
  mount_strategy: copy
  auto_sync: true
  drift_check_on_startup: true
```

## Phase 1：项目启动 — Template Hub

> 目标：5 分钟从零到可运行的 Godot 项目

### 1.1 模板定义与存储

| 任务 | 说明 | 优先级 |
|------|------|--------|
| template.yml 规范定义 | 模板元数据+插件列表+项目配置+导出预设 | P0 |
| 模板存储目录 | `~/.godot-harbor/templates/{template_id}/` | P0 |
| 模板解析引擎 | 读取 template.yml → 解析为 Template 结构体 | P0 |
| 模板验证 | 检查模板完整性（所有插件可获取、引擎版本可下载） | P1 |

### 1.2 模板实例化

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 项目骨架生成 | 创建项目目录 + project.godot + 基础目录结构 | P0 |
| 引擎自动安装 | 检查引擎是否已安装，未安装则自动下载 | P0 |
| 插件自动安装 | 按 template.yml 中的插件列表逐一安装 | P0 |
| .harbor.yml 生成 | 基于模板内容生成项目的 .harbor.yml | P0 |
| 导出预设应用 | 将模板中的导出预设写入项目 | P1 |
| 项目配置应用 | 输入映射、渲染模式等配置 | P1 |
| 实例化进度展示 | 实时展示"正在安装引擎...正在安装插件..." | P0 |

### 1.3 内置模板

| 模板 | 包含内容 | 优先级 |
|------|---------|--------|
| 2D 平台起步包 | Phantom Camera + 输入映射 + 场景组织 | P0 |
| 2D RPG 起步包 | Dialogic + Phantom Camera + 状态机 | P1 |
| 空白项目（推荐插件） | 仅引擎 + 5个推荐插件 | P0 |
| 3D 起步包 | 基础3D场景 + 相机 + 灯光 | P2 |
| 多人游戏起步包 | Nakama 配置 + 网络同步 | P2 |

### 1.4 模板市场 UI

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 模板浏览页 | 分类+搜索+标签筛选 | P1 |
| 模板详情页 | 描述+截图+包含插件列表+评分 | P1 |
| 一键创建项目 | 选择模板 → 选择路径 → 自动实例化 | P0 |
| 模板导入 | 从 Git URL 导入模板定义 | P2 |
| 模板评分/评论 | 社区评价体系 | P3 |

### 1.5 模板保存

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 从现有项目生成模板 | 读取项目的插件绑定+引擎版本+导出预设 → 生成 template.yml | P1 |
| 模板导出 | 导出为可分享的 JSON/YAML 文件 | P2 |
| 模板分享 | 上传到模板市场（社区贡献） | P3 |

### 1.6 交付标准

- [ ] 内置至少2个高质量模板（2D平台+空白推荐）
- [ ] 从模板创建项目全流程可用（选择模板→选择路径→自动安装→可运行）
- [ ] 实例化过程有进度展示
- [ ] 生成的项目包含 .harbor.yml
- [ ] 模板浏览页可用
- [ ] "5分钟开干"体验闭环

## Phase 2：日常开发 — Environment Management

> 目标：让 Godot 项目的开发环境像代码一样可版本化、可复现、可同步

### 2.1 环境漂移检测

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 漂移检测引擎 | 对比 .harbor.yml 声明 vs 实际状态 | P0 |
| 引擎版本漂移 | 检测项目绑定的引擎版本与声明不一致 | P0 |
| 插件版本漂移 | 检测已安装插件版本与声明不一致 | P0 |
| 插件缺失 | 检测声明中有但未安装的插件 | P0 |
| 插件多余 | 检测安装了但声明中没有的插件 | P1 |
| 导出预设漂移 | 检测导出预设与声明不一致 | P2 |
| 漂移报告生成 | 结构化的漂移报告（DriftReport） | P0 |
| 启动时自动检测 | 应用启动时自动检测所有项目的漂移状态 | P0 |
| 分支切换检测 | .harbor.yml 变化时自动触发检测 | P1 |

### 2.2 一键同步

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 同步引擎版本 | 自动下载/切换到声明的引擎版本 | P0 |
| 同步插件版本 | 自动安装/升级/降级到声明的版本 | P0 |
| 同步预览 | 展示即将执行的操作列表（安装/升级/降级/删除） | P0 |
| 同步确认 | 用户确认后执行同步 | P0 |
| 同步报告 | 同步完成后展示结果（成功/失败/跳过） | P0 |
| 部分同步 | 用户可选择只同步部分漂移项 | P1 |

### 2.3 .harbor.yml 深度集成

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 绑定操作自动更新 .harbor.yml | 绑定/解绑插件时自动更新 .harbor.yml | P0 |
| 引擎绑定自动更新 | 绑定/切换引擎时自动更新 .harbor.yml | P0 |
| .harbor.yml 变更监听 | 文件变化时自动触发漂移检测 | P1 |
| 导出预设同步 | 导出预设变更时自动更新 .harbor.yml | P2 |

### 2.4 插件推荐

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 基于项目类型推荐 | 2D项目推荐2D插件，3D项目推荐3D插件 | P2 |
| 基于已有插件推荐 | "使用此插件的项目还使用了..." | P2 |
| 基于模板推荐 | 模板中的插件组合作为推荐来源 | P2 |
| 推荐展示 UI | 项目详情页/首页的推荐区域 | P2 |

### 2.5 交付标准

- [ ] 启动时自动检测所有项目的环境漂移
- [ ] 漂移报告清晰展示（✅/⚠️/❌ 状态标记）
- [ ] 一键同步全流程可用（预览→确认→执行→报告）
- [ ] 绑定/解绑操作自动更新 .harbor.yml
- [ ] .harbor.yml 变化时自动触发漂移检测
- [ ] 团队协作场景验证：成员A修改.harbor.yml → push → 成员B pull → Harbor自动检测漂移 → 一键同步

## Phase 3：构建发布 — Build Pipeline

> 目标：让 Godot 项目的构建发布从"手动折腾"变成"一键完成"

### 3.1 导出模板管理

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 导出模板版本检测 | 检测项目需要的导出模板版本 | P1 |
| 导出模板自动下载 | 未安装时自动下载对应版本 | P1 |
| 导出模板缓存 | 多版本并存，增量下载 | P1 |
| 导出模板健康检查 | 完整性校验 | P2 |

### 3.2 导出预设模板化

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 导出预设数据模型 | ExportPreset 结构体（平台+配置+签名信息） | P1 |
| 预设模板库 | 内置常见平台的导出预设模板 | P1 |
| 预设应用 | 将预设写入项目的 export_presets.cfg | P1 |
| 预设保存 | 从项目当前配置保存为预设 | P1 |
| 预设共享 | 导出/导入预设（JSON格式，可提交Git） | P2 |
| 签名/证书管理 | 安全存储 keystore/证书/Profile | P2 |

### 3.3 多平台批量构建

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 构建任务队列 | 选择项目+平台 → 加入构建队列 | P2 |
| 构建执行 | 调用 Godot headless 导出 | P2 |
| 构建进度展示 | 实时展示构建日志 | P2 |
| 构建产物管理 | 版本号+日期+平台标签+文件路径 | P2 |
| 构建历史 | 构建记录查看+对比 | P2 |

### 3.4 CI/CD 配置生成

| 任务 | 说明 | 优先级 |
|------|------|--------|
| GitHub Actions 模板 | 生成 Godot 导出的 workflow 文件 | P2 |
| GitLab CI 模板 | 生成 .gitlab-ci.yml | P2 |
| 模板变量替换 | 项目名、引擎版本、目标平台等 | P2 |
| 一键写入 | 直接写入项目的 .github/workflows/ 目录 | P2 |

### 3.5 交付标准

- [ ] 导出模板自动管理可用（检测+下载+缓存）
- [ ] 至少2个平台的导出预设模板可用（Windows+Web）
- [ ] 导出预设可保存和共享
- [ ] 批量构建至少支持2个平台

## Phase 4：AI 协作 — MCP Server

> 目标：让 AI Agent 能理解并操作 Godot 项目的完整开发环境

### 4.1 MCP Server 基础框架

| 任务 | 说明 | 优先级 |
|------|------|--------|
| MCP Server 进程 | 独立进程，stdio 传输 | P1 |
| 与 Harbor 数据层集成 | 共享 ~/.godot-harbor/ 数据目录 | P1 |
| 认证/权限 | 只读无需确认，写操作需用户确认 | P1 |

### 4.2 Resources（只读）— P1

| Resource | 内容 |
|----------|------|
| `harbor://projects` | 项目列表 |
| `harbor://project/{id}/environment` | 项目当前环境状态 |
| `harbor://project/{id}/expected` | 项目期望环境（.harbor.yml） |
| `harbor://project/{id}/drift` | 环境漂移报告 |
| `harbor://plugins/available` | 可用插件列表 |
| `harbor://engines/installed` | 已安装引擎列表 |
| `harbor://templates` | 可用模板列表 |

### 4.3 Tools（读写）— P1-P2

| Tool | 功能 | 优先级 |
|------|------|--------|
| `check_drift` | 检测环境漂移 | P1 |
| `sync_environment` | 一键同步项目环境 | P1 |
| `install_plugin` | 安装指定版本插件 | P1 |
| `switch_engine` | 切换引擎版本 | P1 |
| `create_from_template` | 从模板创建项目 | P2 |
| `build_project` | 构建项目 | P2 |
| `check_updates` | 检查插件/引擎更新 | P2 |

### 4.4 Prompts — P2

| Prompt | 功能 |
|--------|------|
| `diagnose_environment` | 诊断环境问题 |
| `suggest_plugins` | 基于项目类型推荐插件 |
| `setup_ci_cd` | 生成 CI/CD 配置 |

### 4.5 客户端集成文档

| 任务 | 说明 | 优先级 |
|------|------|--------|
| Claude Desktop 集成指南 | 配置 harbor-mcp-server 到 claude_desktop_config.json | P1 |
| Cursor 集成指南 | 配置 MCP Server 到 .cursor/mcp.json | P1 |
| VS Code Copilot 集成指南 | 配置 MCP Server 到 VS Code settings | P2 |

### 4.6 交付标准

- [ ] MCP Server 可独立运行
- [ ] 至少7个 Resources 可读取
- [ ] 至少4个 Tools 可调用（check_drift/sync_environment/install_plugin/switch_engine）
- [ ] Claude Desktop 集成验证通过
- [ ] Cursor 集成验证通过
- [ ] AI Agent 可完成"帮我配置这个项目的开发环境"场景
