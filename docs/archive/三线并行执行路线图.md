# Godot Harbor 三线并行执行路线图

> 日期：2026-06-07（v2 — 修订版）
> 三条主线：协议与软著 / MCP 增强 / 推广
> 核心原则：先打磨稳定软件本身，其他工作基于较稳定的版本来做避免返工
> MCP 核心原则：Harbor 只提供 Harbor 独有的数据和能力，不重复造轮子
> 执行状态：**Phase B 部分完成 ✅ | Phase 1+3 MCP 已完成 ✅**

---

## 一、总体策略

### 执行顺序

```
1. 先优化打磨并固化软件本身
2. 基于稳定版本做协议/软著/MCP/推广
3. MCP 只读部分可先行（不依赖核心逻辑稳定）
4. MCP 写操作等核心稳定后再开放
```

### 三个关键决策

1. **协议**：GPL v3 + 商业授权双协议，软著+商标定下来后足以防摘桃子
2. **MCP**：Harbor 只提供数据访问和操作入口，不做智能分析（维护成本极低）
3. **商标**：保留 "Godot Harbor" 名称 + 免责声明（最小改动方案）

---

## 二、总体时间线

```
Phase A: 软件打磨稳定期（当前优先）
    ├── 修复已知问题
    ├── 优化核心功能
    └── 确保核心流程稳定

Phase B: 法律保护 + MCP 只读（与 A 可并行）
    ├── README 添加商标免责声明
    ├── 准备软著材料（基于稳定版本）
    ├── MCP Phase 1：数据访问层（只读，不依赖核心稳定）
    └── GitHub 优化清单

Phase C: MCP 写操作 + 软著提交（核心稳定后）
    ├── MCP Phase 2：环境操作增强
    ├── 提交软著申请
    └── 提交商标注册

Phase D: 推广启动（法律保护 + MCP 就绪后）
    ├── GitHub README 优化
    ├── 社区首发
    └── 视频内容
```

## 四、优先级冲突处理

## 六、风险总览

| 风险 | 影响线路 | 概率 | 应对 |
|------|---------|------|------|
| 软著审批延迟 | A→C | 中 | 推广不依赖软著获批，只需提交 |

| Godot 官方推出类似功能 | B+C | 低 | 强调 MCP + 环境确定性差异化 |
| 一个人做不过来 | 全部 | 中 | 按优先级串行推进，不并行开发 |
